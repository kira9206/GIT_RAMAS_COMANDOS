Antes de comenzar

Conceptos fundamentales

¿Qué es un commit?

Es una captura de los cambios que confirmas en el historial del repositorio. Cada commit tiene un identificador (hash), autor, fecha y mensaje.

git add .
git commit -m "Crear página de inicio"

¿Qué es una rama?

Es una referencia móvil a un commit. Permite trabajar en una línea de desarrollo independiente sin modificar directamente otra rama.

git branch
git switch -c feature/login

¿Qué es HEAD?

Es la referencia que indica dónde estás trabajando actualmente (normalmente el último commit de la rama activa).

git status
git log --oneline --decorate -5

¿Qué es origin?

Es el nombre remoto que suele asignarse al repositorio alojado en GitHub, GitLab u otro servidor.

git remote -v
git fetch origin
Regla útil: antes de ejecutar operaciones que cambien el historial, revisa git status y asegúrate de entender en qué rama estás.

Los 15 temas de gestión de ramas

Explicación + ejemplo
01Introducción a las ramas

Las ramas permiten desarrollar funcionalidades, corregir errores o experimentar sin alterar directamente la versión principal del proyecto.

Ejemplo: tienes una tienda web en main y vas a desarrollar un carrito de compras.

git switch -c feature/carrito

El comando crea la rama y cambia a ella. Luego puedes trabajar y confirmar tus avances con commits.

02¿Qué son las ramas?

Una rama es una referencia a un commit. Al crear una rama, Git no duplica todo el proyecto: crea una nueva referencia desde el commit actual.

Antes: A──B──C main Después de crear feature/login: A──B──C main └─ feature/login
git branch feature/login
git switch feature/login
# Atajo: crear y cambiar
git switch -c feature/registro
03Gestionando ramas

Permite listar, crear, cambiar, renombrar y eliminar ramas locales o consultar ramas remotas.

# Listar ramas locales
git branch

# Listar ramas locales y remotas
git branch -a

# Crear y cambiar
git switch -c feature/perfil

# Renombrar la rama actual
git branch -m feature/perfil-usuario

# Eliminar una rama ya integrada
git branch -d feature/perfil-usuario

# Forzar eliminación local
git branch -D feature/experimento
Atención: -D fuerza la eliminación aunque la rama no esté integrada. Podrías perder commits que no estén en otra referencia.
04Comparando ramas

Compara archivos o commits para saber qué cambiará antes de integrar una rama.

# Diferencias de contenido
git diff main..feature/carrito

# Resumen de archivos cambiados
git diff --stat main..feature/carrito

# Commits que están en feature y no en main
git log --oneline main..feature/carrito

# Historial gráfico de todas las ramas
git log --oneline --graph --all

Ejemplo: antes de integrar el carrito, revisas qué archivos modificó la rama.

05Stash

Guarda temporalmente cambios no confirmados para que puedas cambiar de rama o atender otra tarea. Por defecto guarda cambios rastreados; para incluir archivos nuevos no rastreados utiliza -u.

# Guardar cambios
git stash push -m "Trabajo pendiente del carrito"

# Incluir archivos nuevos no rastreados
git stash push -u -m "Carrito con archivos nuevos"

# Ver la lista
git stash list

# Recuperar y quitar de la lista si se aplica bien
git stash pop

# Recuperar sin quitar de la lista
git stash apply

# Eliminar una entrada
git stash drop stash@{0}

# Borrar todos los stash
git stash clear
Pop vs apply: pop intenta aplicar y después elimina la entrada; apply aplica y la conserva.
06Tipos de merge

merge integra los cambios de otra rama en la rama actual. Los escenarios comunes son fast-forward y three-way. También puedes usar --no-ff para forzar un commit de merge o --squash para preparar un único commit con los cambios.

git switch main
git merge feature/login

# Crear commit de merge aunque sea posible avanzar
git merge --no-ff feature/login

# Preparar los cambios como squash
git merge --squash feature/login
07Fast-forward merge

Ocurre cuando la rama destino no tiene commits nuevos divergentes desde el punto donde nació la rama de trabajo. Git puede mover el puntero hacia adelante sin crear un commit de merge.

Antes: A──B──C main └──D──E feature Después: A──B──C──D──E main, feature
git switch main
git merge --ff-only feature

--ff-only exige fast-forward y falla si no es posible.

08Three-way merge (tres vías)

Se utiliza cuando ambas ramas avanzaron desde un ancestro común. Git compara la base común, la punta de la rama actual y la punta de la rama que quieres integrar. Si puede combinar los cambios, crea un commit de merge.

C──D main / A──B \ E──F feature Después del merge: C──D────M main / / A──B / \ / E──F
git switch main
git merge feature
09Conflictos

Un conflicto aparece cuando Git no puede combinar automáticamente cambios, por ejemplo, cuando dos ramas modifican la misma zona de un archivo.

<<<<<<< HEAD
const precio = 100;
=======
const precio = 150;
>>>>>>> feature/carrito

Edita el archivo y deja el resultado correcto, quitando las marcas. Después:

git status
git add carrito.js
git commit

Si quieres cancelar el merge que está en curso: git merge --abort.

10Conflictos en VS Code

VS Code muestra acciones para resolver conflictos desde el editor.

AcciónQué hace
Accept Current ChangeConserva el bloque de la rama actual (HEAD).
Accept Incoming ChangeConserva el bloque que llega de la otra rama.
Accept Both ChangesIncluye ambos bloques; revisa el orden y posibles duplicados.
Compare ChangesAyuda a comparar las versiones.

Después de resolver y revisar el archivo, márcalo como resuelto:

git add archivo.js
git status
git commit
11Revertir un commit

git revert crea un nuevo commit que aplica el inverso de los cambios de otro commit. Es útil para deshacer cambios ya compartidos sin reescribir el historial.

# Busca el hash
git log --oneline

# Revierte el commit indicado
git revert a1b2c3d

# No abrir editor para el mensaje
git revert --no-edit a1b2c3d
Para revertir un commit de merge se necesita indicar el padre principal, por ejemplo git revert -m 1 HASH. Confirma cuál padre debe conservarse antes de ejecutarlo.
12Archivos de otras ramas

Puedes recuperar un archivo concreto de otra rama sin fusionar toda esa rama. El archivo se copia al directorio de trabajo y queda pendiente de confirmar.

# Traer un archivo desde otra rama
git restore --source feature/carrito -- carrito.js

# Inspeccionar el contenido sin extraerlo
git show feature/carrito:carrito.js

# Luego revisar y confirmar
git diff
git add carrito.js
git commit -m "Recuperar carrito.js"
13Cherry-pick

Aplica en la rama actual los cambios introducidos por uno o varios commits concretos de otra rama. Crea un commit nuevo con un hash distinto.

main: A──B feature: A──B──C──D──E ↑ seleccionar D main después: A──B──D'
git log --oneline feature/login
git switch main
git cherry-pick HASH_DEL_COMMIT

# Si hay conflicto:
# resolver archivos y hacer git add
git cherry-pick --continue

# Cancelar la operación
git cherry-pick --abort
14Rebase

Vuelve a aplicar los commits de tu rama sobre una base nueva. Puede dejar un historial más lineal, pero los commits reaplicados reciben nuevos hashes.

Antes: C──D main / A──B \ E──F feature git switch feature git rebase main Después: A──B──C──D main \ E'──F' feature
git switch feature/login
git rebase main

# Resolver conflictos, luego:
git add archivo.js
git rebase --continue

# Cancelar y volver al estado anterior
git rebase --abort

# Reordenar/editar los últimos 3 commits
git rebase -i HEAD~3
Evita reescribir con rebase commits que otras personas ya usan, salvo que el equipo coordine esa operación.
15Squash merge

Combina el efecto de los cambios de una rama en el índice de la rama actual, para que puedas crear un solo commit. Los commits originales no se incorporan individualmente al historial de la rama destino.

feature: A──B──C──D──E main: A──B──S S = un commit con los cambios
git switch main
git merge --squash feature/carrito
git commit -m "Agregar carrito de compras"
Laboratorio guiado

Ejercicio práctico completo

Escenario: tienda online

Vas a crear una rama para el carrito, guardar trabajo temporal, revisar diferencias y finalmente integrar la funcionalidad en main.

  1. Crear el proyecto:
    mkdir tienda-online
cd tienda-online
git init
git branch -M main
echo "# Tienda Online" > README.md
git add .
git commit -m "Inicializar proyecto"
  2. Crear la rama:
    git switch -c feature/carrito
  3. Crear y confirmar un archivo:
    echo "console.log('Mi carrito');" > carrito.js
git add carrito.js
git commit -m "Crear estructura del carrito"
  4. Guardar temporalmente:
    git stash push -u -m "Trabajo pendiente del carrito"
git switch main
  5. Volver y recuperar:
    git switch feature/carrito
git stash pop
  6. Comparar e integrar:
    git diff main..feature/carrito
git switch main
git merge feature/carrito
Ejecuta los pasos en una carpeta de práctica, no dentro de un proyecto importante. Los comandos echo del ejemplo están pensados para Git Bash o terminales compatibles.

No confundir

Diferencias importantes

ComandosDiferencia principal
merge vs rebaseMerge integra historias; rebase reaplica commits sobre otra base.
merge vs cherry-pickMerge integra una rama; cherry-pick selecciona commits concretos.
merge vs merge --squashMerge registra la integración; squash prepara el efecto de los cambios para un único commit nuevo.
revert vs resetRevert crea un commit inverso; reset mueve la referencia de la rama.
stash vs commitStash guarda temporalmente; commit registra cambios en el historial.
restore vs switchRestore recupera contenido de archivos; switch cambia de rama.
fetch vs pullFetch descarga referencias; pull descarga y luego integra cambios.
